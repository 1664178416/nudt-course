# 小偷逃跑策略详细说明

## 一、策略概述

### 1.1 核心思想

**目标**：在警察追捕中尽可能长时间存活并逃脱

**原则**：**安全第一，逃脱优先** - 在保证安全距离的前提下，寻找最优逃跑路径

### 1.2 策略层次

策略根据发现的警察数量分为三个层次：

1. **无警察**：简单策略 - 向最近边界移动
2. **有警察（1个或多个）**：智能策略 - 多目标评估或寻找突破口

---

## 二、详细策略说明

### 2.1 情况1：没有发现警察

#### 2.1.1 策略描述

当 `enemy_num == 0` 时，即视野范围内没有发现任何警察。

#### 2.1.2 执行过程

1. **计算到四个边界的距离**：
   - 距离左边界：`xdis = 当前位置经度 - 地图左边界经度`
   - 距离右边界：`xdis_right = 地图右边界经度 - 当前位置经度`
   - 距离下边界：`ydis = 当前位置纬度 - 地图下边界纬度`
   - 距离上边界：`ydis_top = 地图上边界纬度 - 当前位置纬度`

2. **选择最近边界**：
   - 计算四个距离的最小值
   - 选择对应最小距离的边界方向

3. **移动方向**：
   - 最近边界是左边界 → 向左移动 `(cos=-1, sin=0)`
   - 最近边界是右边界 → 向右移动 `(cos=1, sin=0)`
   - 最近边界是下边界 → 向下移动 `(cos=0, sin=-1)`
   - 最近边界是上边界 → 向上移动 `(cos=0, sin=1)`

#### 2.1.3 例子

```
小偷位置：(5, 5)
地图范围：(0,0) 到 (10,10)

计算距离：
- 左边界：5 - 0 = 5
- 右边界：10 - 5 = 5
- 下边界：5 - 0 = 5
- 上边界：10 - 5 = 5

所有距离相等，选择任意一个（如向左）
移动方向：(-1, 0)
```

#### 2.1.4 为什么这样设计

- **简单高效**：没有威胁时，直接向逃脱点移动
- **快速脱离**：尽快到达地图边缘，增加逃脱机会
- **节省计算**：避免不必要的复杂计算

### 2.2 情况2：发现警察（1个或多个）

#### 2.2.1 策略描述

当 `enemy_num > 0` 时，即视野范围内发现了至少1个警察，使用**高级智能逃跑策略**。

**重要说明**：无论是发现1个警察还是多个警察，都使用相同的智能策略框架，只是根据包围情况选择不同的子策略。

#### 2.2.2 执行流程

```
发现警察
  ↓
检测是否被包围（需要至少2个警察）
  ├─ 被包围 → 策略2.1：寻找突破口
  └─ 未包围（包括1个警察） → 策略2.2：多目标评估
      ├─ 评估所有候选方向
      ├─ 选择最佳方向
      └─ 如果评分过低，使用Voronoi备选
```

#### 2.2.3 包围检测

**检测条件**：
- 至少需要2个警察
- 警察围绕小偷分布
- 任意两个相邻警察之间的角度差都小于200度

**检测过程**：

1. **收集警察角度**：
   ```
   对于每个警察（在视野范围内）：
     计算角度 = atan2(警察纬度-小偷纬度, 警察经度-小偷经度)
     存储角度和距离
   ```

2. **排序角度**：按角度从小到大排序

3. **计算间隙**：
   ```
   对于相邻警察对：
     间隙 = 下一个角度 - 当前角度
   最后一个间隙 = (第一个角度 + 2π) - 最后一个角度
   ```

4. **判断包围**：
   ```
   最大间隙 = max(所有间隙)
   如果 最大间隙 < 200度 → 被包围
   否则 → 未包围
   ```

**例子 - 被包围**：
```
    警察1(角度: 90度)
      |
      |  小偷
      |
    警察2(角度: 270度)

间隙1：90度到270度 = 180度
间隙2：270度到90度 = 180度（经过360度）
最大间隙：180度 < 200度 → 被包围
```

**例子 - 未包围**：
```
警察1(45度)    警察2(135度)
    \         /
     \       /
       小偷

间隙1：45度到135度 = 90度
间隙2：135度到45度 = 270度（经过360度）
最大间隙：270度 > 200度 → 未包围
```

### 2.3 策略2.1：被包围时寻找突破口

#### 2.3.1 适用场景

- 至少2个警察
- 检测到被包围

#### 2.3.2 执行过程

1. **收集警察信息**：
   - 计算每个警察相对于小偷的角度
   - 存储角度和距离信息

2. **排序角度**：按角度从小到大排序

3. **找到最大间隙**：
   ```
   对于每个相邻警察对：
     计算角度间隙
   找到最大间隙
   ```

4. **计算突破口方向**：
   ```
   突破口角度 = 最大间隙起始角度 + 最大间隙 / 2
   方向向量 = (cos(突破口角度), sin(突破口角度))
   ```

5. **验证和备选**：
   - 如果计算出的方向无效（接近零向量）
   - 则使用多目标评估函数作为备选

#### 2.3.3 例子

```
小偷位置：(5, 5)
警察1：(6, 5) 角度=0度（右侧）
警察2：(4, 5) 角度=180度（左侧）
警察3：(5, 6) 角度=90度（上方）

排序后角度：0度, 90度, 180度

间隙1：0度到90度 = 90度
间隙2：90度到180度 = 90度
间隙3：180度到0度 = 180度（最大！）

突破口角度 = 180度 + 180度/2 = 270度（向下）
方向向量 = (0, -1)
```

#### 2.3.4 为什么这样设计

- **直接针对薄弱环节**：包围圈的间隙是最容易突破的地方
- **最大化逃脱概率**：向间隙中心移动，距离所有警察都较远
- **计算效率高**：只需要角度计算，不需要复杂的评估

### 2.4 策略2.2：多目标评估（核心策略）

#### 2.4.1 适用场景

- **发现1个警察**：使用多目标评估
- **发现多个警察但未包围**：使用多目标评估

**重要**：无论是1个还是多个警察，都使用相同的多目标评估函数，评估函数会自动考虑所有警察的影响。

#### 2.4.2 基本流程

1. **生成候选方向**：
   - 在360度范围内均匀选择24个方向
   - 每个方向间隔15度（360/24=15）

2. **评估每个方向**：
   - 计算移动后的位置
   - 检查是否超出边界
   - 计算综合评分（4个评分项）

3. **选择最佳方向**：
   - 选择评分最高的方向
   - 如果评分过低，使用Voronoi备选

#### 2.4.3 详细评估过程

##### 步骤1：生成候选方向

```
对于 i = 0 到 23：
   角度 = 2π × i / 24
   方向向量 = (cos(角度), sin(角度))
```

**例子**：
```
方向0：角度=0度，向量=(1, 0) 向右
方向6：角度=90度，向量=(0, 1) 向上
方向12：角度=180度，向量=(-1, 0) 向左
方向18：角度=270度，向量=(0, -1) 向下
```

##### 步骤2：计算移动后位置

```
新位置经度 = 当前位置经度 + cos(方向) × 步长
新位置纬度 = 当前位置纬度 + sin(方向) × 步长
```

##### 步骤3：边界检查

```
如果 新位置超出地图范围：
   跳过这个方向（不评估）
否则：
   继续评估
```

##### 步骤4：计算评分（4个评分项）

**评分项1：安全性评分（权重3.0，最重要）**

**目的**：最大化与警察的距离

**计算过程**：

1. **计算当前距离**：
   ```
   对于每个警察：
     当前距离 = sqrt((新位置经度-警察经度)² + (新位置纬度-警察纬度)²)
     更新最小距离
   ```

2. **预测警察位置**：
   ```
   对于每个警察：
     计算警察到小偷的方向向量
     预测移动距离 = min(步长, 当前距离 × 0.8)
     预测警察位置 = 警察位置 + 方向向量 × 预测移动距离
   ```

3. **计算预测距离**：
   ```
   对于每个警察：
     预测距离 = sqrt((新位置经度-预测警察经度)² + (新位置纬度-预测警察纬度)²)
     更新最小预测距离
   ```

4. **安全性评分**：
   ```
   安全距离 = min(最小当前距离, 最小预测距离)
   安全性评分 = 安全距离 × 3.0
   ```

**例子**：
```
小偷位置：(5, 5)，步长=0.5
警察位置：(6, 6)，当前距离=1.41

方向A：向右上，移动后(5.5, 5.5)
- 当前距离到警察：0.71
- 预测警察位置：(5.8, 5.8)
- 预测距离：0.42
- 安全距离：min(0.71, 0.42) = 0.42
- 安全性评分：0.42 × 3.0 = 1.26（低）

方向B：向左下，移动后(4.5, 4.5)
- 当前距离到警察：2.12
- 预测警察位置：(5.8, 5.8)
- 预测距离：1.84
- 安全距离：min(2.12, 1.84) = 1.84
- 安全性评分：1.84 × 3.0 = 5.52（高）

→ 方向B更安全
```

**为什么使用预测**：
- 警察会移动，只考虑当前位置不够
- 预测可以提前规避危险
- 使用较小值（更保守）确保安全

---

**评分项2：边界奖励（权重1.5）**

**目的**：鼓励接近地图边界（逃脱点）

**计算过程**：

1. **计算到四个边界的距离**：
   ```
   距离左边界 = 新位置经度 - 地图左边界
   距离右边界 = 地图右边界 - 新位置经度
   距离下边界 = 新位置纬度 - 地图下边界
   距离上边界 = 地图上边界 - 新位置纬度
   ```

2. **找到最近边界**：
   ```
   最近边界距离 = min(距离左, 距离右, 距离下, 距离上)
   ```

3. **计算奖励**：
   ```
   如果 最近边界距离 < 5个步长：
      边界奖励 = (5个步长 - 最近边界距离) / 步长 × 1.5
   否则：
      边界奖励 = 0
   ```

**例子**：
```
小偷位置：(1, 5)，步长=0.5
地图范围：(0,0)到(10,10)

方向A：向左，移动后(0.5, 5)
- 距离左边界：0.5
- 距离 < 5×0.5=2.5？是
- 边界奖励 = (2.5-0.5)/0.5 × 1.5 = 6.0

方向B：向右，移动后(1.5, 5)
- 距离左边界：1.5
- 距离 < 2.5？是
- 边界奖励 = (2.5-1.5)/0.5 × 1.5 = 3.0

→ 方向A奖励更高（更接近边界）
```

**为什么这样设计**：
- 地图边界是逃脱点，接近边界可以逃脱
- 距离越近奖励越大，鼓励尽快到达边界
- 只在接近边界时给予奖励，避免过度偏向边界

---

**评分项3：方向惩罚（权重-2.0）**

**目的**：避免向警察方向移动

**计算过程**：

1. **对于每个警察**：
   ```
   计算警察指向小偷的方向向量：
     dx = 警察经度 - 小偷经度
     dy = 警察纬度 - 小偷纬度
     距离 = sqrt(dx² + dy²)
     方向向量 = (dx/距离, dy/距离)
   ```

2. **计算方向相似度**：
   ```
   相似度 = 候选方向向量 · 警察方向向量（点积）
   相似度范围：[-1, 1]
   - 相似度=1：完全一致（最危险）
   - 相似度=0：垂直
   - 相似度=-1：完全相反（最安全）
   ```

3. **计算惩罚**：
   ```
   如果 相似度 > 0：
      惩罚 = 相似度² × 2.0
   否则：
      惩罚 = 0
   ```

**例子**：
```
小偷位置：(5, 5)
警察位置：(6, 6)，警察方向=(1, 1)/√2 ≈ (0.707, 0.707)

方向A：向右上(0.707, 0.707)
- 相似度 = (0.707, 0.707)·(0.707, 0.707) = 1.0
- 惩罚 = 1.0² × 2.0 = 2.0（大惩罚）

方向B：向左下(-0.707, -0.707)
- 相似度 = (-0.707, -0.707)·(0.707, 0.707) = -1.0
- 惩罚 = 0（无惩罚）

方向C：向右(1, 0)
- 相似度 = (1, 0)·(0.707, 0.707) = 0.707
- 惩罚 = 0.707² × 2.0 = 1.0（中等惩罚）

→ 方向B最好（远离警察）
```

**为什么使用平方**：
- 平方使惩罚更明显
- 相似度接近1时，惩罚急剧增加
- 鼓励完全远离警察方向

---

**评分项4：包围圈间隙奖励（权重1.0）**

**目的**：如果方向远离所有警察，给予奖励

**计算过程**：

1. **计算方向角度**：
   ```
   方向角度 = atan2(sin(方向), cos(方向))
   ```

2. **对于每个警察**：
   ```
   计算警察角度 = atan2(警察纬度-小偷纬度, 警察经度-小偷经度)
   计算角度差 = |方向角度 - 警察角度|
   如果 角度差 > π：
      角度差 = 2π - 角度差（取较小角度）
   更新最小角度差
   ```

3. **计算奖励**：
   ```
   如果 最小角度差 > 90度：
      奖励 = (最小角度差 - 90度) / 90度 × 1.0
   否则：
      奖励 = 0
   ```

**例子**：
```
小偷位置：(5, 5)
警察1在右方（角度0度）
警察2在上方（角度90度）

方向A：向左下（角度225度）
- 与警察1角度差：225度（>180，取360-225=135度）
- 与警察2角度差：135度
- 最小角度差：135度 > 90度
- 奖励 = (135-90)/90 × 1.0 = 0.5

方向B：向右（角度0度）
- 与警察1角度差：0度
- 与警察2角度差：90度
- 最小角度差：0度 < 90度
- 奖励 = 0

→ 方向A有奖励（远离所有警察）
```

**为什么这样设计**：
- 鼓励选择远离所有警察的方向
- 在多个警察情况下，帮助找到最佳逃跑方向
- 权重较低，不影响主要的安全性考虑

---

##### 步骤5：计算总评分

```
总评分 = 安全性评分 + 边界奖励 + 间隙奖励 - 方向惩罚
```

**例子 - 完整计算**：
```
假设有两个候选方向：

方向A：向右上
- 安全性评分：1.26
- 边界奖励：0（距离边界远）
- 间隙奖励：0（角度差小）
- 方向惩罚：-2.0（向警察移动）
总评分：1.26 + 0 + 0 - 2.0 = -0.74（很差）

方向B：向左下
- 安全性评分：5.52
- 边界奖励：3.0（接近边界）
- 间隙奖励：0.5（远离警察）
- 方向惩罚：0（不向警察移动）
总评分：5.52 + 3.0 + 0.5 - 0 = 9.02（很好）

→ 选择方向B
```

##### 步骤6：选择最佳方向

```
最佳方向 = argmax(所有方向的总评分)
```

##### 步骤7：备选方案

如果最佳方向的评分过低（<50分），使用Voronoi图策略作为备选：

1. **Voronoi策略**：
   - 在16个方向中采样
   - 计算每个方向移动后到所有警察的最小距离
   - 选择最小距离最大的方向

2. **为什么需要备选**：
   - 确保总能找到可行方向
   - 在极端情况下提供保底方案

### 2.5 最终处理

#### 2.5.1 方向归一化

```
方向长度 = sqrt(sin² + cos²)
如果 方向长度 > 0：
   归一化：sin = sin/长度, cos = cos/长度
否则：
   使用默认方向（如远离最近警察）
```

#### 2.5.2 计算最终位置

```
最终经度 = 当前位置经度 + cos(方向) × 步长
最终纬度 = 当前位置纬度 + sin(方向) × 步长
```

#### 2.5.3 边界限制

```
如果 最终经度 < 地图左边界：
   最终经度 = 地图左边界
如果 最终经度 > 地图右边界：
   最终经度 = 地图右边界
如果 最终纬度 < 地图下边界：
   最终纬度 = 地图下边界
如果 最终纬度 > 地图上边界：
   最终纬度 = 地图上边界
```

#### 2.5.4 发送移动指令

将最终位置添加到移动列表，发送给服务器。

## 三、关键算法详解

### 3.1 警察位置预测算法

#### 3.1.1 算法原理

假设警察会向小偷方向移动，但移动距离不超过步长。

#### 3.1.2 计算步骤

```
1. 计算方向向量：
   dx = 小偷经度 - 警察经度
   dy = 小偷纬度 - 警察纬度
   距离 = sqrt(dx² + dy²)

2. 计算预测移动距离：
   预测移动距离 = min(步长, 距离 × 0.8)
   （0.8是预测系数，表示警察会移动80%的距离）

3. 计算预测位置：
   预测警察经度 = 警察经度 + (dx/距离) × 预测移动距离
   预测警察纬度 = 警察纬度 + (dy/距离) × 预测移动距离
```

#### 3.1.3 例子

```
小偷位置：(5, 5)
警察位置：(6, 6)
步长：0.5

计算：
dx = 5 - 6 = -1
dy = 5 - 6 = -1
距离 = sqrt(2) ≈ 1.41

预测移动距离 = min(0.5, 1.41 × 0.8) = min(0.5, 1.13) = 0.5

预测警察位置：
预测经度 = 6 + (-1/1.41) × 0.5 ≈ 5.65
预测纬度 = 6 + (-1/1.41) × 0.5 ≈ 5.65

预测位置：(5.65, 5.65)
```

#### 3.1.4 为什么使用0.8系数

- **保守估计**：假设警察移动80%，留有余地
- **提前规避**：考虑警察移动，提前规避危险
- **平衡性能**：既不过于保守，也不过于激进

---

### 3.2 Voronoi图策略（备选方案）

#### 3.2.1 算法原理

基于Voronoi图的思想，找到距离所有警察最远的区域。

#### 3.2.2 计算步骤

```
1. 在16个方向中采样（每22.5度一个）

2. 对于每个方向：
   a. 计算移动后位置
   b. 计算到所有警察的距离
   c. 找到最小距离

3. 选择最小距离最大的方向
```

#### 3.2.3 例子

```
小偷位置：(5, 5)
警察1：(6, 6)
警察2：(4, 6)

测试方向：
- 方向0度（右）：移动后(5.5, 5)，到警察1距离=1.58，到警察2距离=1.80，最小=1.58
- 方向90度（上）：移动后(5, 5.5)，到警察1距离=1.58，到警察2距离=1.58，最小=1.58
- 方向180度（左）：移动后(4.5, 5)，到警察1距离=2.06，到警察2距离=1.00，最小=1.00
- 方向270度（下）：移动后(5, 4.5)，到警察1距离=2.06，到警察2距离=2.06，最小=2.06（最大！）

→ 选择270度（向下）
```

## 四、策略优势

### 4.1 多目标优化

不是只看一个因素，而是综合考虑：
- ✅ 安全性（最重要，权重3.0）
- ✅ 边界距离（权重1.5）
- ✅ 方向合理性（权重-2.0）
- ✅ 包围情况（权重1.0）

### 4.2 预测能力

考虑警察的移动，提前规避危险：
- 预测警察下一步位置
- 使用保守估计（80%移动距离）
- 选择更安全的路径

### 4.3 动态适应

根据情况自动切换策略：
- 无警察 → 简单策略
- 1个警察 → 多目标评估
- 多个警察未包围 → 多目标评估
- 多个警察被包围 → 寻找突破口

### 4.4 鲁棒性

有备选方案，确保总能找到可行方向：
- 主要策略：多目标评估
- 备选策略：Voronoi图策略
- 边界检查：确保不越界

## 六、关于"是否最优"

### 6.1 说明

这是**启发式策略**，不是理论最优解。

### 6.2 原因

1. **实时性要求**：需要在有限时间内做出决策
2. **信息有限**：只能看到视野范围内的警察
3. **计算复杂度**：理论最优需要全局信息和多步规划

### 6.3 适用场景

- ✅ 单警察追捕
- ✅ 多警察包围
- ✅ 接近边界逃脱
- ✅ 长时间生存

## 七、参数说明

### 7.1 主要参数

1. **候选方向数**：24个（每15度一个）
   - 增加：更精确，但计算量增大
   - 减少：计算更快，但可能错过最优方向

2. **预测系数**：0.8（警察移动距离系数）
   - 增大：更保守，假设警察移动更快
   - 减小：更激进，假设警察移动较慢

3. **评分权重**：
   - 安全性：3.0（最重要）
   - 边界奖励：1.5
   - 方向惩罚：2.0
   - 间隙奖励：1.0

4. **边界奖励触发距离**：5个步长
   - 增大：更早开始向边界移动
   - 减小：更晚开始向边界移动

## 八、总结

在小偷部分的逻辑中，Agent 采用一种**基于多目标评估的智能逃跑策略**。首先，根据发现的警察数量选择策略：如果没有发现警察，直接向最近的地图边界移动；如果发现了警察，则进入智能策略模式。在智能策略中，系统首先检测是否被多个警察包围，如果被包围则寻找包围圈的突破口；如果未包围（包括只有1个警察的情况），则使用多目标评估函数。多目标评估会在24个候选方向中进行选择，综合考虑四个因素：安全性评分（计算到所有警察的距离，包括预测位置，权重3.0）、边界奖励（鼓励接近地图边界逃脱，权重1.5）、方向惩罚（避免向警察方向移动，权重-2.0）和包围圈间隙奖励（如果方向远离所有警察给予奖励，权重1.0）。每个方向的最终评分是这四个因素的加权和，系统选择评分最高的方向作为逃跑方向。如果评估结果不理想，还会使用Voronoi图策略作为备选方案，确保总能找到可行方向。这样既能避开附近的警察，又能高效地向安全区域移动，实现智能突围。
